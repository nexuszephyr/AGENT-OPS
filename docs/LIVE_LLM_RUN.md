### First-run findings

- **Fixed: starting the plan used up the 8-call budget.**
  - Plan steps now carry `missing_mandatory`, and the prompt says not to call `fill_form` until the conversation gives all of them.
  - `context_block` has a compact profile.
  - The prompt says to skip blocked (`after`) steps.
  - Result: no NEEDS_INFO calls, no `fetch_customer`, and no turn above 7.
- **Fixed: invented question ids.** The prompt says `question` is only for `pick_next_question` ids. Form fields go in `to_officer` and the new `needs_from_officer`. Result: 0 `question_replaced` events in 30 turns (the `_vet_question` backstop is unchanged).
- **Fixed: a rejection fixed only one form.**
  - `REVISION_PROMPT` lists the pending siblings.
  - In every run the model revised PMJJBY and refilled PMSBY and SSY with `fill_form`; refills keep `prepared_by` and maker-checker.
- **Fixed: reply text said UNKNOWN while the panel said VERIFY_MANUALLY.** Highlights now take the engine's final statuses after `_finish` (tested). D2 passed 3/3.
- **Fixed: no daughter's details in DEMO.md, so SSY was never queued.** The Priya line now gives them, and B1 asserts an SSY form (3/3).
- **Better: slow turns.** The max fell from 30.4 s to 17.3 s and the median is about the same, while each run now does more. A UI spinner and a faster routing model are still open.
- **Fixed (optional strengthening): crop confirmation enforced only by the prompt.** `grows_notified_crop` / `in_notified_area` are now officer-only, refused from the agent with "officer must confirm via the fact form". A3 checks that the chat can't set them (3/3) and that the fact form does.
- **Resolved: `update_profile` on a bare "hello" (unverified).** The harness now records tool args. It was an empty-facts call; those are now refused (see below).
